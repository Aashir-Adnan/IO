# IO Phase 1.5 — Conversational Shell Design

> Extends `docs/superpowers/specs/2026-09-07-io-phase-1-design.md`. Phase 1 (storage
> pipeline), Plan 2 (query pipeline), Plan 3 (service + desktop), and Plan 4
> (voice) are done. This phase turns the transactional store/query surface into a
> continuous conversation with a real desktop client.

## 1. Vision & scope

IO stops feeling like a form you submit to and starts feeling like something you
talk to. Three things change:

1. **The service remembers the conversation.** The last several turns feed
   `route` / `plan` / `phrase`, so follow-ups resolve ("what about last week?",
   "and Sana?"). Extraction and storage stay strictly per-utterance — the
   LLM-boundary rule is untouched.
2. **Voice lives in the app.** Whisper and Piper move into the service. A mic
   in the desktop client records audio, the server transcribes it, runs the one
   pipeline, synthesises the reply, and the client speaks it back. `io listen`
   (CLI) becomes a thin client of the same endpoint.
3. **The desktop client is rebuilt** in the **Nocturne** design system
   (`docs/design/`) — a quiet, instrumented, dark interface with a central voice
   orb. Fullscreen by default.

### In scope

- Conversation persistence (`conversations` / `messages` tables) + a live
  in-memory turn buffer for prompt context.
- `Backend` gains conversation context on `route`/`plan`/`phrase` and a new
  `acknowledge()` for a natural STORE reply.
- `POST /voice` (audio in → transcript + answer + synthesized audio out),
  `GET /voice/health`.
- A richer `TurnResponse` with structured `cards` (record cards, provenance).
- A **Memory Inspector**: `GET /entity/{type}/{id}` → the facts IO recalled about
  an entity, with confidence and source record ids.
- **Standby data**: `GET /standby` → greeting name, headline stats, and the
  surfaced chips (tasks today, next occasion, next appointment-like record).
- The Nocturne desktop client: window chrome, rail, and three working states —
  **Standby**, **Listening**, **Conversation + Memory Inspector**. Simulated
  typing + deliberate pacing. Fullscreen.

### Deferred (backlog, not this phase)

- **State 1d — task runner.** Autonomous multi-step work with approval gates,
  live logs, and telemetry (`docs/design/IO Desktop.dc.html` §1d). This is an
  agent loop with tool use — a real departure from the deterministic pipeline.
  The nav destination can exist as a stub.
- **External-source provenance** (`CALENDAR · MESSAGES` in §1c) — Phase 2
  ingestion.
- **Entity-file browser** — Timeline / Sources / Review stay placeholders.
- Real token streaming (Anthropic supports it; `/ws` streaming stays deferred —
  the client simulates typing on complete responses).
- Kokoro / a more natural TTS engine — a `Speaker` adapter swap.

## 2. Visual system — Nocturne

The design system is imported at `docs/design/nocturne/` (token sheet
`styles.css`, guide `readme.md`) and the four-state mockup at
`docs/design/IO Desktop.dc.html`. Those files are the source of truth; this
section records only what the build must honour.

- **Ground / surfaces:** `--color-bg #161826` (the window) on `#0f111c` (behind
  it), `--color-surface #232532`, panel `#1b1d2b`, borders from the neutral ramp
  (`#292b31` / `#33364a` / `#3f424d`). No pure black, no pure white.
- **Accent:** a single blurple `#9184d9` with a 100–900 ramp
  (`--color-accent-400 #b5abfc` … `--color-accent-900 #2b2741`). Used as a
  **line and a glow, never a flood** — the orb core, an active rail icon, a
  focused input border, a spinning progress arc, tag outlines.
- **Type:** **Inter** 300/400/500 for everything readable; **IBM Plex Mono**
  400/500 for the instrumented bits — kickers, telemetry readouts, timestamps,
  status chips, logs (`letter-spacing` .08–.16em, often uppercase). Headings are
  size-and-space, never bolder than 500.
- **Icons:** **Phosphor** (regular). The set the mockup uses: `waveform`,
  `chat-teardrop-dots`, `brain`, `list-checks`, `users-three`, `gear`,
  `microphone`, `circle`, `check-circle`, `check`, `arrow-up`, plus a CSS
  spinner. Vendor these ~12 as inline SVG — no icon-font, no CDN.
- **Shape / elevation:** radii 4 / 8 / 14; elevation is `--shadow-lg`
  (`0 0 0 1px #9397ab, 0 16px 40px rgba(0,0,0,.65)`) — an edge plus ambient
  darkness, never stacked shadows.
- **Rules fade at the ends** — `linear-gradient(90deg, transparent, #3f424d 12%,
  #3f424d 88%, transparent)`. Box outlines and short accent marks stay solid.
- **Motion:** ambient and slow — the orb breathes and its rings rotate
  (`io-spin` 14–120s, `io-halo`, `io-breathe`); a caret blinks during
  transcription/streaming; a mic blip pulses. All gated by
  `prefers-reduced-motion`.
- **Interaction states are themed** — `:focus-visible { outline: 2px solid
  var(--color-accent); outline-offset: 2px }`, hover/pressed tints from the
  accent ramp, `::selection` an accent tint. Never a browser default.

### Local-first vendoring (the hard rule stands)

The mockup links Google Fonts, unpkg Phosphor, and uses `@import`. The shipped
`frontend/` does none of that:

- `frontend/vendor/fonts/` — Inter (300/400/500) and IBM Plex Mono (400/500) as
  subsetted `woff2` (Latin + punctuation; ~30–45 KB total), loaded via local
  `@font-face`. Fallbacks: `system-ui` / `ui-monospace`.
- `frontend/vendor/icons.js` — the ~12 Phosphor SVGs as an inline map.
- `frontend/tokens.css` — the Nocturne `:root` variables and ramps, copied from
  `styles.css`, plus the app-specific additions (`--color-page #0f111c`, orb
  gradients).
- `tests/test_frontend_assets.py` continues to fail the build on any non-local
  `http(s)://`.

## 3. Backend — conversation layer

### 3.1 Schema (`0003` migration)

```
conversations(
  id            bigserial pk,
  title         text,                       -- first user line, trimmed; editable later
  started_at    timestamptz not null default now(),
  last_at       timestamptz not null default now()
)
messages(
  id               bigserial pk,
  conversation_id  bigint not null references conversations(id) on delete cascade,
  role             text not null,            -- 'user' | 'assistant'
  text             text not null,
  kind             text,                     -- assistant only: answer|ack|gate|unknown|error
  intent           text,                     -- 'store'|'query'|'unknown'
  source           text not null default 'text',  -- text|voice
  utterance_id     bigint references utterances(id) on delete set null,
  audio_ms         integer,                  -- assistant only, when spoken
  created_at       timestamptz not null default now()
)
```

Indexes: `messages(conversation_id, created_at)`, `conversations(last_at desc)`.
Utterances are still logged as today; `messages.utterance_id` links the two.

### 3.2 `io_assistant/conversation/`

- `store.py` — `ConversationStore(session_factory)`:
  - `create() -> int`, `active_id() -> int | None` (most recent by `last_at`),
    `ensure_active() -> int`
  - `append(conv_id, role, text, *, kind=None, intent=None, source="text",
    utterance_id=None, audio_ms=None) -> int` — inserts a message, bumps
    `last_at`, sets `title` from the first user line if unset. Own commit.
  - `recent_turns(conv_id, n=6) -> list[Turn]` — last `n` messages, oldest first
  - `history(conv_id, before_id=None, limit=50) -> list[Message]` — paged, newest
    first, for the client
  - `list_conversations(limit=40) -> list[ConversationSummary]`
- `context.py` — `Turn` dataclass (`role`, `text`), `format_context(turns,
  max_chars=1400) -> str` — renders `you: …\nio: …` lines, newest-truncated to
  the cap. Pure.

### 3.3 `Backend` protocol change

```python
class Backend(Protocol):
    def route(self, utterance: str, *, context: str | None = None) -> Intent: ...
    def extract(self, utterance: str, now: datetime) -> ExtractionResult: ...   # unchanged
    def plan(self, question: str, now: datetime, *, context: str | None = None) -> dict: ...
    def phrase(self, question: str, rows: list[dict], shape: AnswerShape,
               *, context: str | None = None) -> str: ...
    def acknowledge(self, extraction: ExtractionResult, *, context: str | None = None) -> str: ...
```

- `context` is the string from `format_context` (or `None`). Prompts gain a
  `{context}` slot rendered as a "Recent conversation:" block, or omitted when
  empty. `route.txt`, `plan.txt`, `respond.txt` updated; new `acknowledge.txt`.
- **`acknowledge`** replaces the deterministic `"Stored: event …"` string with a
  natural one line ("Logged — dinner with Nafay at Arcadian this evening, tied to
  his birthday."). It is phrasing, not deciding: it may only restate what
  `persist_store` actually wrote (record kinds/titles, resolved entity names, the
  grounded dates), passed to it as a compact fact list. `_summarize`'s structured
  output becomes the `cards` payload and the fallback string if `acknowledge`
  fails.
- `LocalBackend` / `AnthropicBackend` / `HybridBackend` / `FakeBackend` all
  implement the new signatures. `FakeBackend` records the `context` it received
  (`fake_backend.last_context`).

### 3.4 `Orchestrator`

`handle(text, *, source="text", captured_at=None, confirmed=False, pending=None,
conversation_id=None, history=None) -> HandleResult`

- `history` is the pre-formatted context string; the service supplies it.
- The router, planner, and phraser calls thread `context=history`.
- STORE success → `message = backend.acknowledge(extraction, context=history)`
  wrapped so a failure falls back to `"Stored: " + _summarize(...)`.
- `HandleResult` gains `cards: list[Card]` (see §5) and `intent_kind: str`
  (`answer` | `ack` | `gate` | `unknown` | `error`).
- The Orchestrator does **not** touch the conversation tables — the service owns
  that (so the CLI `io repl` / `io store` paths keep working unchanged, with
  `history=None`).

### 3.5 Service wiring

`create_app` builds a `ConversationStore`. Per turn (`/utterance`, `/voice`,
`/ws`): `conv = store.ensure_active()` (or the body's `conversation_id`) →
`store.append(conv, "user", text, source=…)` → `history =
format_context(store.recent_turns(conv))` → `orchestrator.handle(text,
history=history, …)` → `store.append(conv, "assistant", result.message,
kind=result.intent_kind, intent=result.intent, audio_ms=…)`. The in-memory
`recent_turns` read is the live context; the table is the durable record.

New endpoints: `GET /conversation?id=&before=` (paged messages),
`POST /conversation` (start new, returns id), `GET /conversations` (list).

## 4. Backend — voice endpoint

- **`POST /voice`** — `multipart/form-data`: `audio` (a WAV blob, 16 kHz mono
  PCM16 — the client encodes it), optional `conversation_id`, optional `speak`
  (`"1"`/`"0"`, default `"1"`). Flow: write to a temp WAV →
  `Transcriber.transcribe` → the same turn flow as `/utterance` →
  if `speak`, `Speaker.synthesize(reply.message)` → respond:
  ```
  { transcript, transcript_confidence, ...TurnResponse, audio_b64 }
  ```
- **`GET /voice/health`** — `{ whisper: bool, piper: bool, voice: str,
  reason: str | null }`. The client enables/disables the mic from this.
- `WhisperTranscriber` + `PiperSpeaker` are built lazily on the first `/voice`
  hit and cached on `app.state`; a text-only user never loads a model. When a
  model is missing, `/voice` returns `503` with `{reason}` and the client shows
  the mic disabled with that reason as a tooltip.
- **`io listen`** (CLI) is refactored to `POST /voice` — capture (push-to-talk /
  VAD) stays local, everything else is the one server path. `io serve` must be
  running; `io listen` checks `/voice/health` first.
- `[voice].tts_voice` selects the Piper voice (candidates in §2 of the Phase 1
  spec / this document's intro). Default pending the user's audition.

## 5. Backend — response shape

Every turn endpoint returns:

```
TurnResponse = {
  kind:            "answer" | "ack" | "gate" | "unknown" | "error",
  intent:          "store" | "query" | "unknown",
  text:            "<markdown>",
  shape:           "text" | "markdown" | "diagram",
  cards:           [ Card, ... ],
  pending_token:   str | null,
  conversation_id: int,
  message_id:      int,
  audio_b64:       str | null       // /voice, or auto-speak
}

EntityRef = { etype: "person"|"place"|"item"|"occasion", id: int, name: str }

Card =
  | { type: "record", record_id, kind, domain, title,
      entities: [EntityRef],            // resolved links, in link order
      when: <ISO|null>, due: <ISO|null>, status: <str|null> }
  | { type: "tasklist", items: [ { record_id, title, status, due: <ISO|null> } ] }
  | { type: "sources", record_ids: [int], count: int, labels: [str] }   // "3 MEMORIES USED"
```

- STORE ack → one `record` card per written record.
- QUERY answer → a `sources` card (record ids the ranker actually used) and,
  when the answer is a list of actionable records, a `tasklist` card. The prose
  in `text` still stands alone; cards are enrichment.
- Gate → `kind: "gate"`, `text` carries the reason + the yes/no ask,
  `pending_token` set.

## 6. Backend — Memory Inspector & Standby

### 6.1 `GET /entity/{etype}/{id}` — the inspector panel (§1c right side)

`etype` ∈ `person|place|item|occasion`. Returns:

```
{
  etype, id, name, subtitle,          // "SISTER · 41 NOTES" -> role + record count
  facts: [ { label, text, record_ids: [int] } ],   // "RECALLED NOW", "CONSTRAINT", "LAST YEAR"
  confidence: 0.0..1.0,               // mean rank/similarity of the facts' source records
  sourced_from: int                   // distinct source records behind the facts
}
```

`facts` is derived deterministically: the entity's linked records, most-recent
first, each rendered as `{label from kind/domain, text from title/body,
record_ids}`. `confidence` is the mean of those records' vector similarity to the
entity embedding (already computable). No new model call — this is retrieval +
formatting.

### 6.2 `GET /standby` — the Standby view (§1a)

```
{
  greeting_name: str,                 // config [ui].name, default from $USER
  stats: { memories: int, recall_ms: int, clock: <ISO> },
  chips: [ { icon, text, record_id | null } ]   // "3 tasks today", "Priya's birthday in 11 days", "Dentist, Thu 14:30"
}
```

`memories` = `count(records)`. `recall_ms` = a rolling mean of the last N query
latencies held in `app.state` (0 until the first query). `chips`: open
`task`/`chore` records due today (count), the nearest future `occasion`, and the
nearest future `record` with a `due_at` — deterministic queries.

## 7. Frontend — the Nocturne desktop app

`frontend/` is rebuilt. Vanilla ES modules, no framework, no build step,
everything vendored (§2). The mockup `docs/design/IO Desktop.dc.html` is the
visual reference for every measurement, colour, and animation.

### 7.1 Shell

- **Window**: fullscreen by default (`[ui].fullscreen`, F11 toggles). A 36 px
  title strip — three inert dots, `IO 1.4`, and a right-side status readout that
  changes per state (`LOCAL · ENCRYPTED` / `● MIC LIVE` / `7 RECALLS · 0 WRITES`).
- **Rail** (62 px): the orb glyph, then the Phosphor nav — `waveform`
  (Talk/Standby), `chat-teardrop-dots` (Conversation), `brain` (Memory —
  placeholder), `list-checks` (Tasks — placeholder for 1d), `users-three`
  (People — placeholder), `gear` at the bottom. The active destination's icon
  takes the accent.
- **Main**: the active view. `state.js` (subscribe/emit store) + `api.js`
  (fetch + the WS) + `views/{standby,listening,conversation}.js` +
  `components/{orb,bubble,card,inspector,composer,typing}.js`.

### 7.2 The orb (`components/orb.js`)

One component, four visual modes driven by a `mode` prop
(`standby|listening|thinking|speaking`), built from the mockup's layered rings:
a masked `repeating-conic-gradient` tick ring, a dashed counter-rotating ring, a
transparent ring with one accent arc (`border-top-color`) spinning, a
`radial-gradient` halo, and a bright core (`radial-gradient` + accent glow
`box-shadow`) that breathes. `listening` swaps the core for the vertical
`io-bar` waveform and speeds every rotation; `speaking` pulses the halo with the
playing audio's amplitude (Web Audio `AnalyserNode`). Reduced-motion freezes
rotation, keeps a static ring.

### 7.3 States

- **Standby** (§1a): `GET /standby` → "Good morning, {name}.", the mono stat row,
  the orb centred and large, the chips, and the composer with the push-to-talk
  hint. The chips are buttons — clicking one sends it as a question.
- **Listening** (§1b): entered by the mic button or `⌥Space`. Records via
  `vendor/recorder.js` (Web Audio → 16 kHz mono WAV, ~90 lines). While
  recording: the orb in `listening` mode, a live level meter, and `GAIN / VAD /
  ELAPSED` mono readouts. The "RECALLING" entity chips shown mid-speech in §1b
  need interim transcription (partial Whisper) and a match call — **deferred to
  backlog**; Listening mode ships without them. Release / click / `⌥Space` again →
  `POST /voice` → the transcript lands as the user bubble, the view switches to
  Conversation, the answer types in and (auto-speak = voice) plays.
- **Conversation + Memory Inspector** (§1c): the transcript — user bubbles right
  (`#1b1d2b`, 10 px radius), IO replies left with the small orb avatar; inline
  `record` / `tasklist` cards; the `sources` line (`brain` icon + "N MEMORIES
  USED"). A streaming caret while the answer types. The **right panel** appears
  when a reply's top `record` card has an `entities[]` — the client calls `GET
  /entity/{etype}/{id}` for `entities[0]` → the inspector (avatar, `RECALLED NOW`
  / `CONSTRAINT` / `LAST YEAR` facts, the
  `CONFIDENCE` bar + "86% · SOURCED FROM 3 NOTES", an "Open …'s file" button that
  is inert for now). The composer is the compact "Reply to IO" bar with mic +
  `arrow-up`.

### 7.4 Pacing (`components/typing.js`)

On send: the user bubble appears at once; after ~150 ms an IO bubble with the
`io-bar` thinking indicator and an italic status line ("thinking through your
week…"); held a minimum of `[ui].min_think_ms` (600) even for an instant reply;
then the reply text reveals at `[ui].typing_cps` (45 char/s, faster past 240
chars), the markdown re-renders on completion, cards fade in, and the inspector
slides in. `Esc` stops playback and finishes the reveal immediately.

### 7.5 Config `[ui]`

```toml
[ui]
name          = "Sam"        # greeting name; falls back to the OS user
fullscreen    = true
auto_speak    = "voice"      # "voice" | "always" | "never"
typing_cps    = 45
min_think_ms  = 600
```

### 7.6 Desktop shell (`io run`)

`webview.create_window(..., fullscreen=config.ui.fullscreen, text_select=True)`,
min size 960×640, remembered geometry in `~/.local/share/io/window.json`, a
native menu (New Conversation / Reload / copy-paste). `io run` still reuses a
running service (Plan 3 change) and `dev.ps1 up -Window` still drives the full
lifecycle.

## 8. Testing

- **Conversation store** (DB): create / append / title-from-first-line /
  `recent_turns` cap / `history` paging / `list_conversations` ordering.
- **Context formatter** (pure): turns → capped string, newest kept.
- **Backend context plumbing**: `FakeBackend.last_context`; Orchestrator passes
  the formatted history to route/plan/phrase; `acknowledge` fallback on failure.
- **`acknowledge`**: Fake returns a set string; real prompt renders the fact
  list; a raising backend falls back to `_summarize`.
- **Response shape**: `/utterance` STORE → a `record` card with the resolved
  names; QUERY → a `sources` card with the ranker's record ids.
- **`/voice`** (TestClient + fixture WAV + injected `FakeTranscriber` /
  `FakeSpeaker`): transcript in the response, `audio_b64` present, two `messages`
  rows persisted, `source="voice"`. `GET /voice/health` shape.
- **Memory inspector**: seed an entity + linked records → `GET /entity/person/{id}`
  returns facts with `record_ids` and a `confidence` in `[0,1]`.
- **Standby**: seeded data → `GET /standby` chips and stats.
- **Frontend**: asset lint (no CDN, no `@import`, fonts + icons local); a pure
  unit test of `vendor/markdown.js` and the typing scheduler via a tiny node
  runner if `node` is present, else a documented manual check; a DOM smoke that
  boots `app.js` against a mocked `api.js` and asserts the three views render.
- **Local-first**: the `tests/test_e2e_store.py` socket guard still passes — the
  voice path opens no non-local sockets (Whisper/Piper are local; the client
  talks only to `127.0.0.1`).
- Backend parity: the STORE and QUERY e2e scenarios run through `/utterance`
  with a `FakeBackend`, asserting the same DB outcomes plus the new `cards`.

## 9. Staged implementation

Two plans, each leaving a working system.

**Plan 5 — conversational backend** (`docs/superpowers/plans/…-io-phase-5-*.md`):
`0003` migration; `conversation/` store + context; `Backend` context params +
`acknowledge`; `Orchestrator` history threading + `cards`; `POST /voice` +
`/voice/health` + lazy model cache; `io listen` refactor; `TurnResponse` reshape
across `/utterance` `/voice` `/ws`; `GET /entity/…`, `GET /standby`,
`/conversation(s)`. Full `@requires_db` + TestClient coverage. The CLI keeps
working throughout.

**Plan 6 — Nocturne desktop client**: vendor Inter + Plex Mono + Phosphor +
`tokens.css`; the shell (window, rail, status); `orb.js`; `recorder.js`;
Standby, Listening, Conversation + Inspector views; typing/pacing; fullscreen +
window geometry + native menu; asset-lint + DOM-smoke tests. Timeline / Sources /
Review / Tasks stay routed placeholders.

**Backlog after this phase**: state 1d task runner (agent loop + approval
gates + telemetry + log); external-source provenance; entity-file browser; real
`/ws` token streaming; Kokoro `Speaker` adapter.
